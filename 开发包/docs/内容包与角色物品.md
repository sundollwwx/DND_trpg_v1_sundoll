# 内容包、冒险进度与角色物品

本文记录 2026-10-01 存档重构的当前实现约定。正式切换状态以维护记录为准；旧 v4 切换报告中的目录、数量和验收结果仅代表当时状态。

## 身份与归属

同级目录仍是主程序、通用包、战役包、玩家包及运行数据；开发包和创作包位于程序包外层。主程序不持有玩家背包。SQLite 协调库是当前事务数据源，各包 JSON 是归属模块的持久化投影，不能单独拿旧投影覆盖新数据库。

| 对象 | 身份 | 保存内容 |
| --- | --- | --- |
| 来源内容包 | `content-package.id` | 通用或战役来源、稳定身份及安装可用性 |
| 一场冒险 | `campaignId` | 地图、场上棋子、当前进度和启用内容包清单 |
| 玩家 | `playerId` | 账号、所属角色与伙伴 |
| 角色 | 稳定角色 ID | 成长、资源、独立背包与钱包 |
| 物品模板 | 模板 ID、版本、`contentPackageId` | 可发放或放置的通用/战役定义 |
| 已持有物品 | 实例 ID、`ownerCharacterId` | 获得时的资料快照、数量、状态及原始来源 |

同一来源战役可以新开多场冒险。各场使用不同的战役、地图和场上棋子身份，复用同一来源内容包与模板定义。角色换团延续自己的背包和消耗，不会按每场冒险重新发一套。

## 三种物品来源

- **通用**：`sourceScope=general`，指向通用内容包。
- **战役**：`sourceScope=campaign`，指向战役内容包；`sourceCampaignId` 记录原始战役来源，不作为当前冒险 ID 使用。
- **角色专属**：`sourceScope=personal`，保存在角色所属玩家包。`sourcePlayerId`、`sourceCharacterId` 记录原始来源，创建时以 `boundCharacterId` 绑定角色；不进入全局物品模板目录。

`sourceTemplateId` 和 `sourceTemplateVersion` 记录获得时的模板版本。模板以后更新不应覆盖已发放实例的历史版本和正文。迁移仅补充缺失来源，不把历史实例升级到模板的最新版本。

角色专属物品仅由主持人显式解绑后才能转交。解绑移除当前绑定限制，转移改变持有人，原始来源不变；已解绑物品由当前持有人保管，不要求原玩家包一直安装。普通编辑、另存模板和放置地图不得悄悄将角色专属来源改成通用或战役来源。

## 每场冒险的启用内容

`content-selection` 按当前 `campaignId` 保存 `sourcePackageId`、`enabledPackageIds` 和操作回执。没有显式选择时，默认启用目前可用的通用包以及自身来源包。保存选择后清单保持明确；自身来源包必选，其余包可以按团选择。

通用/战役物品需同时满足“来源已安装可用”和“当前冒险已启用”。未满足时，角色仍拥有实例，但玩家响应不提供它的物品资料，也不能使用、转移或恢复到可用列表。主控可通过“启用内容包”检查来源状态；当前背包界面没有停用物品明细入口。重新启用恢复原剩余数量、状态、备注和正文。角色专属物品按持有人与绑定条件校验，不经过战役启用清单。

前后端都使用当前战役上下文；内容选择变更后旧页面操作需刷新或重新选择。接口的版本校验和操作编号防止旧请求覆盖新选择、重复发放或重复扣除。

## 分享、安装、卸载

便携包写入 schema 4，并兼容 schema 3 导入。内容包身份独立于 ZIP 安装记录和新开冒险 ID，模板用稳定 `contentEntryId` 识别来源定义。通用包更新和同源战役新开不会重新生成角色背包。

玩家包携带角色物品实例与 `contentDependencies` 来源说明，导入后不会自动安装或启用依赖内容包。依赖缺失时保留实例，补齐来源并启用后恢复可用。角色专属物品不加入战役内容包选择。共享通用/战役包禁止混入角色专属来源和玩家身份字段。

卸载来源保留已发放实例和已有冒险进度；其普通物品因来源缺失而暂停使用。重新安装同一来源能够恢复引用。整套恢复仍需要相互一致的数据库、模块记录和资源，不能把不同日期的文件夹拼接成一份存档。

## 迁移与核查

`server/content_packages.py`、维护核查与迁移回执使用 `server/sqlite_read.py` 的共用连接：优先 `mode=ro`；仅当已有文件因缺少 WAL 辅助文件等原因报 `unable to open database file` 时，回退为 `mode=rw` 并立即启用 `query_only=ON`。回退不能新建数据库，允许 SQLite 创建空的 WAL 协调文件；不写权威数据或表结构，不执行迁移或待发布写入，不忽略活动 WAL。旧的本地来源用确定性身份识别；`migration_plan(overrides)` 生成只读预览，`apply_migration(plan)` 才在事务中注册来源、补来源字段与初始化每场冒险的内容清单。

维护命令入口为 `开发包/maintenance/migrate_content_origins.py`：默认预览，显式 `--apply` 需已审查的方案哈希与外部维护报告路径。它先获取服务器独占锁、创建完整备份，再复核哈希并执行事务；成功后自动调用保真核查。服务运行、备份失败或原档变化均拒绝来源迁移，不在应用启动时自动运行。

需要人工确认的旧物品按不可变实例 ID 提供归属，不能仅靠名字合并。迁移需保留实例 ID、数量、所属角色、正文、备注、收藏、使用状态、垃圾箱，以及已经存在的模板 ID 和版本。方案记录迁移前指纹与方案哈希；原档变化后拒绝使用旧方案。

使用 `开发包/maintenance/verify_content_migration.py` 对只读迁移前备份和迁移后数据库核查。应在启动隔离服务与 UI 验收前执行，否则正常操作产生的变动也会被报告。脚本逐条比较全部原文档及其归属、修订，独立要求业务文档只新增来源字段，并核查新增来源/选择记录和迁移回执。它不代替浏览器交互、HTTP 授权与素材文件验收。

创建独立 SQLite 快照时，使用备份 API 完成复制后，在快照连接上执行 `PRAGMA journal_mode=DELETE`，关闭后再供只读核查使用。这样快照无需临时创建 WAL 辅助文件。此设置仅用于独立备份文件，不修改正式运行库；不要用 `immutable=1` 读取有活动 WAL 的数据库，否则可能漏读最新事务。
