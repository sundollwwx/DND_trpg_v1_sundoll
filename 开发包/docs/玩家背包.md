# 玩家背包

## 角色与入口

玩家从冒险台顶部打开背包。默认选择主角色；选择器分别列出角色和伙伴。切换后钱包与物品一起切换。每个角色拥有独立物品与钱包，跨地图、跨战役保留。地图册、日志和个人棋子使用冒险台各自的入口。

桌面背包窗口保持固定大小，每行六格；较窄窗口按四格、三格排列。右侧显示简短效果和常用操作，完整规则与故事从「查看详情」打开，信件和书籍从「阅读」打开。

## 使用与转移

普通消耗品：选物品 → 使用，扣一件并记录。持有物品：选物品 → 使用，只记录，不减少件数。文书使用阅读入口，容器不提供普通使用按钮。

治疗药水：选物品 → 使用 → 点击目标。使用者自动采用物品所属角色。服务器一次提交数量与目标生命值，再用同一回执播放现有骰子动画；生命值不超过上限。主控可从记录撤销符合版本条件的治疗。

转移：选物品 → 转移 → 点击接收角色。数量默认一件，可先改数量。两边背包同时保存；只有定义、来源、绑定条件、角色归属和备注等合并条件一致时才合并。不同来源、不同正文或备注的物品不合并。收藏是一个开关。

同一玩家不同角色之间整组转移也合并相同物品。选择接收人期间若物品资料或接收角色身份已变化，先更新窗口，保留有效的转移数量；若物品已移走，则关闭转移窗口。

没有治疗联动的物品只扣数量或记录使用；法术、持续状态、充能等由玩家和主控处理，不根据说明文字自动执行规则。

## 内容来源与角色绑定

通用、战役物品引用来源内容包；角色已领取的实例仍保存在角色背包。当前战役只显示并允许操作其已安装、已启用来源包的物品。停用或缺失来源不会删除实例，也不会重置数量；重新启用后恢复原状态。主控可在“启用内容包”检查来源状态；当前没有停用物品明细入口。普通发放、领取、使用与转移仍由服务端校验来源。

“角色专属”是独立来源类型，属于玩家包，不进入大物品库。创建时绑定接收角色；跨战役无需启用来源战役包。主控在转移时明确确认解除角色绑定，再转交给接收角色。`boundCharacterId` 表示当前绑定限制，`sourcePlayerId`、`sourceCharacterId` 记录原始来源；解绑或转交不会把来源改成接收角色。解绑后不再依赖原玩家包继续安装。

编辑物品资料、数量、正文、备注不会改写来源；另存模板与地图放置也保留来源边界。详见 [内容包与角色物品](内容包与角色物品.md)。

## 垃圾箱与主控编辑

玩家弃置一件时直接移入垃圾箱；多件时填写弃置数量再提交。玩家可以收回自己弃置的物品，不能恢复主控删除的记录，也不能永久删除记录。

主控在居中的编辑窗口修改已发放物品的资料；价格和重量并排，冲突与保存错误直接显示在窗口内。其他物品的同步更新不会清空草稿，同一物品变化需要载入更新后再保存。主控也可调整数量、删除物品。数量改为零进入垃圾箱。主控可恢复、永久删除单条记录，或确认清空当前玩家的整个垃圾箱。垃圾箱按玩家保存，包含其角色的记录；恢复回原所属角色。相同正文、来源、角色、备注与收藏的物品合并为一格，不同内容保持独立。用完的零数量记录继续保留用于回执与撤销，但不计入在持物品的 300 种上限。

物品库分模板、通用物品、战役物品。编辑模板可以直接保存，不要求同时发放或放置。模板归档后可恢复或永久删除；已经发放和放置的副本保持独立。修改副本不会改写模板。

## 地面物品与宝箱

「固定位置」和「允许拾取」相互独立。固定控制移动，拾取控制玩家领取；禁止领取时仍可查看。模板可设置地图默认属性，放置后主控可单独覆盖。

地面物品：打开 → 领取，默认交给主角色一件；领取选项可选角色和数量。宝箱：打开 → 选箱内物品 → 领取。玩家可同时查看宝箱，领取由服务器校验版本和数量。主控可编辑箱内正文、效果、数量，删除箱内物品、取出到地图或发给玩家。

地图预览只显示短效果与操作，完整资料统一从「查看详情」打开，文书从「阅读」打开。其他标记更新、同一标记仅改变位置时，不会清空正在填写的数量或开锁加成；非位置属性变化时刷新预览并核验原按钮。主控未保存的草稿保留并提供「载入更新」。未确认的地图操作按地图与玩家身份暂存，切回后仍使用原操作编号核对。

旧式宝箱也可编辑容器资料，保留箱内物品和原锁状态。箱内物品取出到地图时采用它自己的固定、拾取默认属性。

锁定状态与固定位置独立，普通锁和秘法锁沿用现有流程。点击与拖动保留六像素区分阈值；大小按网格，位置不吸附。

## 同步与临时窗口

成功修改背包、钱包或地图领取后，房间仅广播匿名更新信号。客户端通过本人已鉴权的背包接口读取最新数据；通知不包含玩家编号、名称、物品或财产。连续信号合并处理，关闭的背包不发起读取；打开期间用四秒轮询作为补充。

同步保留备注、调整数量和主控编辑草稿，同时更新物品预览。旧按钮核验物品和接收角色；同一目标已变化时重新核对。关闭背包、切换玩家、战役或内容包时，转移、使用、钱包和编辑窗口一并关闭，旧窗口不能继续操作。

## 保存与恢复

当前模块存档由 `程序包/运行数据/存档/模块存储/模块.sqlite3` 协调事务。角色物品与钱包属于玩家模块，地图物品属于战役模块，模板属于对应通用或战役模块。发布与重载沿用 `workspace.py`；本次不建立另一个物品数据库，也不将旧 JSON 恢复成当前数据源。

写操作校验版本和操作编号，保存失败时整笔回滚。结果未知时使用「核对并重试」，复用编号避免重复扣除或发放。旧战役背包迁移保留物品、垃圾箱、备注、收藏和原文件备份；损坏数据停止迁移，不覆盖原档。

已经提交但响应丢失的操作，在战役或启用内容包变化后仍可核对原回执。服务器先校验登录身份、原编号和原命令签名，只读确认已经保存的结果，不执行旧操作、不重复投骰或广播。返回的物品按当前内容包过滤，之后客户端正常读取当前角色与接收人。没有回执或命令被改动时，旧请求继续被拒绝。

每场冒险单独保存 `content-selection`，指定来源包和启用包清单；接口同时校验战役上下文，旧页面不能沿用先前战役的选择继续发放或使用。日常战役保存不会覆盖该清单或角色物品的权威来源；隐藏物品和垃圾箱记录仍保存在玩家包。读取与启动不会自动改写旧来源，正式迁移先生成预览，再显式应用。

备份和恢复按项目的整套存档流程操作，读取旧地图不会返还消耗品。服务端更新需保存战役、关闭主控台后再重启，并刷新双方页面。
