# 部署与维护

核对日期：2026-10-20。日常操作见 [使用说明](../../程序包/使用说明.md)，数据位置见 [目录导览](../../程序包/目录导览.md)。

## 服务与入口

根目录统一启动器支持 `local`（本机服务）、`auto`（本机服务与公网连接）、`--port`、`--no-open`、`--check`。本机服务默认端口 8090。启动器会复用兼容服务，日常只保留一个负责运行的启动窗口。网站网页由用户手动打开。

公共主站源码在 `网站/主站/`，通过 `网站/build_site.py` 发布到 Cloudflare Pages；留言 Worker 源码在 `网站/留言板/`，数据保存在 D1。账号、房间及 DM/玩家端来自本机 Python 服务。静态主站可用不代表账号和房间服务在线。

本机网络配置在 `程序包/运行数据/联机设置.json`：`webEntrances` 指定主站、玩家与管理员域名；`cloudflareTunnel` 指定固定隧道入口与私有令牌文件；`launcher.openBrowser` 保持 false。公网连通性由实际服务探测判断，不通过修改 DNS、代理等系统设置来掩盖失败。

## 邮箱账号

已有安装：进入 `程序包/主程序/` 后运行 `python3 manage_accounts.py check` 查看私有配置位置和准备状态；不能用初始化命令覆盖已有配置或存档。

干净 Git checkout／新发行包需要 Python 3.9 或更新版本。先在 `程序包/主程序/` 执行：

```sh
python3 manage_accounts.py init --origin https://play.example.com \
  --smtp-host smtp.example.com --smtp-port 465 --smtp-security ssl \
  --smtp-user YOUR_SMTP_USER --smtp-from noreply@example.com
python3 manage_accounts.py set-smtp-secret
python3 manage_accounts.py check
```

域名、SMTP 主机、用户名和发件邮箱都替换为自己的配置。账号域名使用 HTTPS 默认 443 端口；`init` 会同步写入新安装的 `联机设置.json` 账号域名白名单，并保持禁止自动打开浏览器，但不会配置 DNS 或隧道。SMTP 三项可以暂时全部省略，完成后在私有 `运行数据/认证/邮箱账号设置.json` 补齐；发信服务未就绪时不能完成邮箱注册。`init` 只建立中央账号房间模式与配置，不创建旧 DM 工作区、不创建账号、不发送邮件。已有数据、旧模块、运行中服务或不匹配的半成品配置会使初始化停止；若首次写入中断，只允许补完该命令创建的准确空安装标记。

随后回到项目根目录运行 `启动桑哆尔之歌.command local`（Windows 使用 `.bat local`），手动打开窗口显示的 `/account#dashboard`。注册并验证邮箱后创建角色、创建房间。新房间的生活与天气资料来自 `主程序/defaults/日常小事`，房间副本独立保存；更新程序不会覆盖已有房间的资料。

账号使用邮箱与密码，注册与找回密码在原网页输入邮箱验证码。`enabled` 控制邮箱账号，`roomsEnabled` 控制账号房间；当前网页版使用账号房间模式。账号页为 `/account`，`#dashboard` 进入个人主页。密码长度规则由前后端共同校验。

发信设置包含 `publicOrigin` 与 SMTP 的 `host`、`port`、`security`、`username`、`from`。密钥通过 `SUNDOLL_SMTP_PASSWORD` 或 `python3 manage_accounts.py set-smtp-secret` 的隐藏输入配置，不写进源码、命令参数或聊天。配置检查通过不等于已完成真实投递验证。

修改配置后，先保存并完整停服，再重启；已有进程不会自动重读全部设置。公网不通时不应把验证失败判断成账号丢失。`roomsEnabled: false` 及旧 DM 登录仅为旧工作区兼容，不是当前账号产品的操作流程。

## 存储与备份

账号直接拥有角色；角色、背包和钱包的权威库在 `运行数据/账号角色/`，房间以身份编号关联。旧玩家包用于迁移与恢复，不按昵称自动合并，不重复复制已绑定角色。

全安装备份使用根启动器的 `--backup`，恢复使用 `--restore`，校验使用 `--verify-backup`。须先让所有 DM 保存并完整关闭服务；工具同时锁住中央服务和房间。备份涵盖中央账号、全站角色及其素材、历史归档、全部房间与检查点，不包含主程序及机器发信/隧道凭据。

网页单工作区备份与全安装备份格式、覆盖范围不同。恢复中断时使用 `--recover-backup` 明确回滚，不能手动拼接不同日期的数据库与资源。

## 代码、测试与发布

- 空白网页发行：`python3 开发包/build_distribution_v4.py --destination /绝对路径/新发行目录`。默认只使用源码中的公开资料，原工作区归档后也可构建；不得把现有运行数据当作默认输入。
- 标准内容发行：额外传 `--standard --source /隔离工作区/运行数据/存档`。来源必须明确选择；构建者要审阅其中被标为通用的内容。资料进入 `主程序/defaults/`，新房间首次启动时安装。已存在的发行目录和 ZIP 不会被覆盖。
- 全项目检查：`python3 开发包/maintenance/check_project.py --node /绝对路径/node`，测试写入临时存档。
- 只升级功能时替换主程序，保留内容模块和运行数据。
- 主站构建与留言服务分别发布，参见 [网站说明](../../网站/README.md)。修改本地文件不等于线上已更新。
- 桌面 App 暂停，不继续打包或发布；网页公共素材缓存继续保留。

源码中的公开默认资料也是规则测试与生活文档导出的来源，不再重复维护另一份测试 JSON。测试需要修改资料时，先复制到临时房间；不得读取作者账号、战役或历史归档。`check_project.py` 会清除继承的生产工作区选择和 SMTP 密钥，再运行临时目录中的测试。

账号与房间私有目录已被 Git 忽略。忽略规则不能移除已经提交过的内容；新增分发方式仍须检查实际产物，不能直接把整个工作目录压缩发送。

## 原工作区归档

当前产品使用账号房间模式。中央 `运行数据/存档/` 只保留定位标记与服务锁，游戏写入必须进入具体房间。已有安装可以把原工作区归入 `运行数据/历史归档/<归档名>/`；归档包含差异版本与旧凭据，应当私有保管，不能作为日常服务启动。新安装不包含作者的历史归档。不要删除模式标记来绕过入口规则。

离线维护工具 `开发包/maintenance/archive_original_workspace.py --root 程序包` 默认只预览；`--apply` 完整停服后归档，`--verify 归档路径` 校验，`--rollback` 回滚中断事务。存在归档事务记录时启动会停止，避免读取一半新、一半旧的数据。需要找回历史时先制作隔离副本，不将旧数据库直接拼到当前房间。
