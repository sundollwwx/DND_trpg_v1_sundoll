# 日常小事 · 通用生活资料

主控台入口：**世界**。时间与天气、食宿生活、钓鱼和菜单是直接打开弹窗的一级入口，与场景快捷功能使用同一套样式。通用包仍以“日常小事”保存生活资料。菜单可单独展示给玩家；预览不会自动展示，也不会自动扣钱、改变 HP 或完成角色恢复。

本包以 **D&D 2024 / SRD 5.2.1** 为规则依据。中文内容是本项目的规则摘要与改写，非官方译文。规则摘要、地方创作与模拟参数分开保存，不能将原创菜名、天气权重或随机事件当作官方规则。

## 公开默认资料来源

| 文件 | 内容与边界 |
| --- | --- |
| `资料/lifestyle.json` | 官方生活费、每餐食费、每夜房费、普通服务、休息、食水需求、觅食与环境规则摘要；每项附版本和来源。 |
| `资料/menus.json` | 玩家可见菜单。标准食宿档位采用 2024 价格；菜名、口味、店规、款待和自定酒款是地方创作。 |
| `资料/flavor.json` | 六种停留环境、三张各 20 项的日常风味表、六种可选社区习惯；只生成叙事细节。 |
| `资料/climate.json` | 原创气候模型的季节、昼夜温度曲线、小时 Markov 转移权重与调度参数；环境规则摘要单独注明官方来源。 |
| `资料/fishing-tables.json` | 此前设计的 24 张 d20 钓鱼房规表，作为可选扩展保留。 |

主程序负责读取、计价、模拟和展示，本目录保存随程序发布的公开默认资料。每个新房间首次初始化时复制一份，房间里的后续修改独立保存，升级程序不会覆盖。修改公开默认菜单时先改 `menus.json`，再运行 `python3 开发包/生活玩法/export_menus.py` 同步两份已有餐食文档；加上 `--check` 可只检查是否一致。脚本应从项目根目录调用，也支持使用脚本的绝对路径。

## 官方规则与创作的边界

生活费按**每人每日**计算，已包含基础食宿；逐项食宿则按**每人每餐、每人每夜**计算。采用生活费时，不重复收取已包含的同档餐费与房费。报价不代表实际成交，贵族生活费是最低价格，赤贫的零费用不保证获得食物或住所。

短休、长休、生命骰、每日食水需求和力竭使用 2024 规则；角色自身特性的例外仍然适用。较贵房间不自动缩短休息、增加恢复或保证休息成功。世界时间中的休息按钮只推进相应时段并播放场景，主持人仍需确认休息条件，再处理实际恢复。

觅食依据相应环境的感知（求生）检定。属性检定的自然 1 或 20 不自动失败或成功；`flavor.json` 的 d20 只是挑选一个叙事细节，不会自动引发战斗、罚款、伤害或机械增益。社区习惯是可替换的地方设定，不代表整个物种统一的饮食或性格。

气候模型属于本应用的原创实现。小时 Markov 权重、气候带、季节划分、昼夜曲线和天气持续方式均不是 SRD 提供的官方天气生成表；官方内容只用于判断实际环境效果。沿用旧战役的 **7 日／周、52 周／年，共 364 日**世界历，不把它称作所有 D&D 世界的通用历法。模型按游戏时间的整点推演；关闭自动变化后保留天气、风力与基温，显示温度仍随昼夜曲线变化。普通雨天不能直接等同于达到官方条件的暴雨，危害由主持人按实际场景、暴露和角色特性判断。

气候资料 v2 为温带、寒带、热带、干旱、海洋和高山分别保存天气、风力及天气风力三张转移矩阵，再用季节候选池调整概率。队伍所在地与地图的“地点”关联，同一地点的不同楼层共用气候。在“队伍所在地与气候”选择地点和当地气候，按“确认抵达”才切换；主控预览或向玩家展示地图不代表队伍抵达。各地点保存自己的天气和小时锚点，返回时补推离开期间的小时，重复确认同一地点不会重新抽取。尚未指定地点的旧战役保留现有天气。地区缓存只保存到主持人战役存档，玩家只收到当前天气，不公开未到达地点的气候与缓存。

薄雾、浓雾、普通雨雪、暴雨和大雪分别说明适用规则。浓雾造成重度遮蔽；黑暗视觉不能透雾。天气界面只提示规则，不自动给角色添加目盲、伤害或力竭。旧版“强风／酷热”天气标签继续读取，但新生成只用独立风力和实际温度描述它们。v1 气候配置读取时明确迁移到 v2；自行改写概率时仍须保证各季节的每行有合法后继。

旧钓鱼表的低点惩罚、自然 1／20 奖惩、战斗、奖励和岩浆钓鱼条件都是既有房规。岩浆池表仍保留此前设计的黑曜石鱼竿、魔法鱼饵等器具与条件；本次日常生活扩展**没有新增装备或魔法物品**。严格使用官方规则时，按觅食规则裁定钓鱼，并由主持人描述实际渔获；不要把旧表的奖惩混入官方求生检定。

## 一段停留怎样主持

1. 打开时间与天气，确认当前时间、天气和实际光照；抵达新地点时确认所在地与当地气候，再按行程推进时间。
2. 打开食宿生活，约定采用生活费还是逐项食宿，填写人数、天数、餐数与住宿晚数，核对报价后再记账。
3. 选择停留地点，用一道菜、一个住宿细节或一条店规呈现当地生活；需要时抽取 d20 风味细节。
4. 在菜单中预览地点食单，点“展示给玩家”后才广播；结束时可收起玩家菜单。
5. 有休息或食水问题时查看“休整”；只有结果不确定且失败有意义时才要求相应检定。照规则处理资源与恢复，再继续场景。

## 更新、发行与备份

本模块随标准版和空白版发行，默认源位于 `程序包/主程序/defaults/日常小事/`；初始化后的房间副本位于该房间的 `通用包/日常小事/`。安装级完整备份包含房间副本，程序源码另行发布。在冒险管理的“通用包”中可导出日常资料为 `.sundoll`，在另一工作区导入并启用。导出包含完整的五份 JSON 和已有说明文件；导入、启用和发行前都会验证资料格式，不允许把任意文件混入资料模块。

本机资料和导入来源都可以停用、恢复。停用保留原资料，暂停日常资料与天气功能；恢复后重新读取。更新导入来源时，逐份资料保留本机改动，并报告未覆盖的文件。模块发布失败时读端暂停，下一次协调库连接会重放已经提交的完整更新，避免读到只更新一半的资料。现有目录清单的 `portable: false` 是旧版元数据，经过启用或停用发布后会更新为 `portable: true`；便携导出不依赖该旧字段。

修改房间副本 JSON 后，刷新主控台与玩家页面，以清除生活资料、钓鱼表和菜单的前端缓存。修改 `climate.json` 尤其需要重新加载 `/api/daily-life/climate.js` 配置脚本；只关闭并重开弹窗不会重新加载气候常量。若同时更新了服务端读取或路由代码，先保存战役并关闭主控台，再重启服务，然后刷新页面。缺失或不合法的数据会报告读取错误，不会静默生成另一套内容替代。
