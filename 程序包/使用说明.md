# 桑哆尔之歌 · 模块工作区

## 玩家名字登录

在玩家首页选择“已有玩家”，输入玩家名字登录；新玩家选择“注册新玩家”。名字不存在时提示创建，不自动生成游客。账号名去除首尾空格、统一全半角并忽略英文字母大小写后判重，主持人创建、玩家注册、改名及玩家包导入都遵循这一规则。

只有玩家账号名必须唯一，角色仍可同名。账号改名不改变内部身份、角色与背包归属。名字是当前唯一登录凭据，知道名字即可登录。登录码输入、复制、修改与重置入口已停用；邮箱密码接口仅预留，当前未开放。

## 启动

双击外层启动器，或进入主程序文件夹双击其中的启动器。需要 Python 3.9 或以上版本。主程序文件夹可以改名，也可以单独复制到一个空目录使用。

| 同级模块 | 保存的内容 |
| --- | --- |
| 主程序 | 主控台、玩家页面、服务器与界面主题 |
| 通用包 | 通用棋子、物品与共享素材；私人收藏单独归属 |
| 战役包 | 各战役的地图、NPC、敌人、物品、资料与冒险进度 |
| 玩家包 | 玩家角色、持久伙伴、各角色的独立背包 |

运行数据保存本机登录资料、跨模块保存协调和缓存。活动模块与运行数据共同组成工作区，请使用界面管理，避免手动拼接不同日期的目录。

完整工程还可以在“程序包”旁边附带“开发包”和“创作包”。它们分别用于测试发布与保存制作原稿，均不是主程序运行依赖，也不会进入空白版或标准发行版。

## 日常使用

首页的“冒险管理”集中处理工作区事务；开团主控台右上角保留棋子库、物品库等常用工具，存档菜单保留保存当前进度与返回主页：

- **战役**：打开、新建、归档或恢复战役；导出战役内容或进度。地图封面和其他战役编辑仍从“战役封面与管理”进入。
- **玩家**：查看所有玩家及角色数量，进入角色名册与登录管理，导出玩家包。
- **通用与模块**：打开棋子库、物品库，导出通用收藏，导入、更新、启用或卸载来源模块。
- **备份与恢复**：备份整套工作区、下载私人备份、导入备份及恢复。

日常“保存当前进度”保存当前战役。角色成长、装备、背包、血量与剩余资源独立保存在玩家包中；读取旧战役不会将角色回退，也不会自动恢复血量。角色与伙伴不会自动进入大棋子库。

棋子库保存会保留模块归属。其他页面或模块操作更新棋子库后，旧页面不能直接覆盖新版；可先导出本页数据留底，再点击“重新载入”。

## 角色背包与发放

每件持有物品属于一个具体角色，不设玩家公共仓库。主控从玩家背包或物品库发放时选择接收角色；地图宝箱发放和玩家领取也直接进入所选角色背包。同名角色通过生命上限、AC 区分，内部使用固定身份编号。没有角色的账号需先创建角色。

玩家只能查看自己名下角色的背包，物品可以在同账号的角色之间整叠转移。切换角色只切换查看对象，切换战役不会重置物品。旧玩家包只有一个角色时，未分配物品自动归入该角色；有多个角色且归属不明时，启用会停止并提示先确定归属。恢复旧整套备份后，主持人可在背包中查看“待分配旧物品”并指定角色，这只是旧数据修复入口。

## 导入、更新与卸载

选择 `.sundoll` 后先查看导入信息，再确认安装。战役内容包可以多次“新开一场冒险”，每场独立。玩家包保持角色身份；已有同身份角色的当前成长不会被导入覆盖。跨机器续团时，在来源处停止操作并成套导出进度与各玩家包；也可用整套私人备份迁移。

更新来源模块不会覆盖已经开团的进度或玩家角色。通用包更新后点击“启用／更新通用库”，系统更新未被本机编辑过的模板，并列出保留的本机修改。来源历史保留在工作区中。

“卸载来源”可以恢复：通用库中未改动的来源模板会移除，手动修改保留；已放置棋子、已发放物品、已有战役和玩家档案保留。卸载不会立刻清理原始素材。

## 整套备份与恢复

整套备份包括战役、玩家、背包、通用库、原始素材、运行协调资料和本机登录凭证，不包含主程序。备份按文件校验，恢复前自动创建当前状态的备份。

恢复会重启服务，将所有模块一起回到所选时间。请先让玩家停止操作，并关闭其他主控和棋子库页面；本页完成后自动刷新，其他页面需要刷新并重新登录。恢复中断时，重新运行启动器即可继续，避免混用不同时间的数据。

私人备份可下载为 ZIP，并在另一套同级模块工作区导入。它包含登录凭证，请作为私人存档保管。分享内容请使用战役、玩家或通用模块导出，它们不包含登录码。

## 分享与升级主程序

- **只给主程序**：对方首次启动得到空工作区，没有你的战役、账号或私人收藏，可自行新建和导入。
- **标准发行包**：主程序加公开通用棋子和物品，没有作者的战役和玩家资料。
- **战役或玩家模块**：使用“冒险管理”导出后交给对方导入。
- **升级程序**：关闭服务后替换主程序，保留同级内容模块和运行数据。

正式模块目录是运行中的工作目录；安装和卸载请通过界面操作。不要直接删除协调数据库，也不要把活动模块目录当成可随意拖入的分享包。
