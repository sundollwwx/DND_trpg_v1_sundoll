# 桑哆尔之歌 · 项目目录导览

核对日期：2026-09-22。日常操作见 [使用说明](使用说明.md)，本次问题与验证见 [项目检查报告](../开发包/设计文档/项目整体检查-20260922.md)。

## 整个项目如何分工

主程序提供操作能力，通用包提供可复用内容，战役包保存各场冒险，玩家包保存跨战役角色。四者在文件系统中同级；运行数据负责把它们安全地连接起来。

```text
桑哆尔的世界/
├─ 启动桑哆尔之歌.command     Mac 启动入口
├─ 启动桑哆尔之歌.bat         Windows 启动入口
├─ 程序包/
│  ├─ 主程序/                界面、服务、运行逻辑
│  ├─ 通用包/                通用模板与共享资料
│  ├─ 战役包/                每个战役独立的内容与进度
│  ├─ 玩家包/                玩家、独立角色、伙伴、背包
│  ├─ 运行数据/              登录认证、协调记录、缓存与备份
│  ├─ 使用说明.md            日常使用与迁移方法
│  └─ 目录导览.md            本文
├─ 开发包/                   测试、迁移、构建、修复和内部设计资料
├─ 创作包/                   原图、候选、提示词、音乐工程与备团稿
├─ 旧恢复备份/               已退出日常运行的旧工程与迁移留存
├─ 旧发行包/                 已过期的发行目录和同名 ZIP
├─ .git/                     版本历史，不是游戏运行数据
├─ .gitignore                哪些文件不提交到版本库
├─ .gitattributes            版本管理中的文件处理约定
└─ .idea/                    开发工具本机设置
```

“程序包”是产品工作区，可以脱离开发包和创作包运行。开发包读取并检查主程序，创作包向通用包和战役包提供审核后的完成品；主程序不反向依赖这两个包。这些目录不是 Git 分支；本次查看到的本地 Git 分支只有 `main`。

## 主程序

| 目录或文件 | 作用 |
| --- | --- |
| `主控台/主控台.html` | 主持人首页和跑团界面 |
| `主控台/host/` | 主控台逻辑、样式、冒险管理、物品库、备团手册、音乐与文档窗口 |
| `主控台/玩家.html`、`主控台/player/` | 玩家登录、地图操作、个人状态 |
| `主控台/shared/` | 主持人与玩家共用的背包、日志、个人角色库、旅行篮子、地图物品和骰子界面 |
| `主控台/vendor/` | 随程序带入的第三方代码，当前包括 Three.js |
| `shared/` | 通信版本、工作区会话、尺寸与规则等基础逻辑 |
| `server/` | 本地服务、权限检查、读写存档、模块导入导出、玩家身份与资源管理 |
| `server/domain/` | 日志、天气、数值等业务数据处理 |
| `asset/地图/` | AI 地图 Prompt 创作台与旧地图兼容渲染器；当前战役的地图资源由战役包管理 |
| `asset/棋子库/` | 完整棋子库编辑器、立绘工作台与种子入口 |
| `asset/界面/` | 品牌图、主页背景、休息动画、旅行篮子外观等程序主题资源 |
| `launch_sundoll.py` | 启动流程、端口与连接等准备 |
| `start_server.py` | 服务启动入口 |
| `模块.json`、`distribution.json` | 主程序模块与发行格式标记 |

把“主程序”与空的通用包、战役包、玩家包和运行数据放入一个新工作区，就可以启动并建立自己的内容。它仍包含界面图片、音效和可选联机组件，“空白版”指没有原作者的战役、玩家与私人存档，不是没有任何图片。

## 通用包

| 子目录 | 作用 |
| --- | --- |
| `本地通用/` | 通用生物、魔宠、物件和通用物品模板及对应资源 |
| `私人收藏/` | 单独归属的私人收藏，不能因为放在通用包就默认公开 |
| `本地资料/资料/音乐/` | 共享音乐，以及当前扫描器兼容的战役音乐分类 |
| `本地资料/资料/文档/` | 共享文档目录及说明 |

“通用”是使用范围，不等于素材已有公开分发许可。

## 战役包

目前包括 `c184-烬鳞讨伐-2026.8.8`、`c286-风骸岛之龙`、`test-测试` 和 `default-默认战役`。是否归档由管理数据决定，目录存在不代表它应显示在当前战役列表。

| 战役内部 | 作用 |
| --- | --- |
| `模块.json` | 身份、版本及资源归属等信息 |
| `当前存档.json` | 当前冒险的地图、摆放、流程、场景和进度等状态 |
| `记录/` | 模块的版本化数据记录，供协调保存与恢复使用 |
| `资源/` | 地图、棋子与立绘等资源，采用内容哈希命名 |
| `资料/` | 战役文档、音乐等附属资料 |
| `封面.jpg` 等 | 首页战役封面 |
| `自动备份/` | 该战役的历史恢复材料 |

当前风骸岛文档实际位于 `战役包/c286-风骸岛之龙/资料/文档/战役/c286-风骸岛之龙/`。这里暂时保留了文档扫描器需要的内部层级；不宜只为目录好看而手动移平。

## 玩家包

每个玩家文件夹采用“玩家姓名--短编号”，例如 `雷弗--26e6896f`。姓名便于查找，短编号用于区分同名玩家；完整 playerId 仍保存在档案内部，用于登录、角色和背包关联。通过程序修改玩家名时，文件夹会同步更新；不要手动移动或改名。里面的 `当前档案.json`、`记录/`、`资源/` 管理该玩家的角色、长期伙伴、图片和持有物品。

新版首次启动会先建立整套备份，再将旧编号目录调整为姓名目录。迁移保留全部文件内容、登录码和角色身份，并同步资源索引；中断后通过迁移记录继续完成。

- 同一玩家可以有多个独立角色；两个黑胡桃仍是同账号的两个角色。
- 每个角色分别保存成长、血量、资源与背包；发放和领取物品时直接选择接收角色。
- 木木是桑哆尔的持久伙伴。
- 同一角色跨战役延续状态，切换战役不会自动恢复或倒退成长。
- 个人角色通过玩家档案、背包中的个人棋子入口管理，不自动进入大棋子库。

`物品库自动备份/` 是备份目录，不是另一个玩家。

## 运行数据

| 子目录 | 作用与注意点 |
| --- | --- |
| `存档/` | 当前索引、工作区配置、兼容数据与模块存储数据库 |
| `存档/模块存储/` | 模块注册、版本协调和导入导出暂存；不能作为普通缓存删掉 |
| `协调记录/` | 多个模块共同更新时的一致性记录 |
| `认证/` | 本机登录与身份资料，应保持私有 |
| `.sundoll-cache/` | 可重新生成的显示和联机缓存；运行中不手动删除 |
| `恢复备份/` | 程序以后生成新恢复点的活动位置；旧材料已移出程序包 |
| `整套备份/` | 可将各模块和认证一起恢复的私人完整备份，不含主程序 |
| `迁移留存/` | 程序以后生成新迁移留底的活动位置 |
| `运行日志/` 及切换报告 | 启动、排错和核对记录 |

活动模块与运行数据共同构成当前工作区。分享模块使用界面导出 `.sundoll`；迁移整套私人环境使用整套备份。不要把几个不同日期的文件夹手工拼在一起。

## 创作包

一级目录 `../创作包/`，不在程序包内部，也不参与日常运行。

| 子目录 | 作用 |
| --- | --- |
| `制作历史/` | 历次图像、地图等制作与调整材料 |
| `立绘制作/` | 立绘流程与规范 |
| `音乐制作/` | 制作记录、候选、小样、母带和工程资料 |
| `界面设计/` | 不参与运行的界面原图与待审核图；当前含旅行篮子设计源文件 |
| `物品立绘制作/` | 物品图片、提示词、入库请求与验收记录 |
| `备团/` | 备团稿、审核与准备材料 |
| `旧状态/` | 过去状态的参考留存 |
| `回收站/` | 暂留的废弃创作材料，确认后才能清理 |

这里通常不参与日常运行，但可能是重新制作和证明来源的唯一依据。

## 开发包

一级目录 `../开发包/`，不在程序包内部。普通主持人运行发行版时不需要它。

| 子目录 | 作用 |
| --- | --- |
| `maintenance/` | 项目检查与修复入口 |
| `tests/` | 用临时数据执行的回归测试 |
| `docs/` | 使用手册、维护记录与历史文档 |
| `设计文档/` | 模块架构、迁移计划、核对结果和本次审计 |
| `github/` | 上传、下载与同步辅助脚本 |
| `代码恢复点/` | 修改前的代码副本 |
| `发行候选/` | 自用构建与迁移验证的输出位置；旧构建已移出程序包 |
| `同级模块待切换/` | 下一次同级结构切换使用的活动暂存位置；旧暂存已归档 |
| 根部迁移、打包、验证脚本 | 开发和升级时用，不需要每次开团运行 |

公网联机使用的可选 `cloudflared` 位于 `主程序/bin/`，因为它属于运行能力。测试、构建和迁移脚本则只存在于开发包。

## 一级历史归档

`旧恢复备份/` 当前保存 2026-09-21 同级切换前的完整旧工程与迁移留存，合计约 5.6 GiB。`旧发行包/` 保存同日生成的六套旧候选目录及其 ZIP，合计约 1.5 GiB。两者均不参与当前运行，也不会作为现行发行包使用；暂时保留是为了还能恢复和复核。

## 应当怎样迁移与升级

| 目的 | 应使用的内容 |
| --- | --- |
| 在自己的另一台设备安装空程序 | 经检查的空白构建包 |
| 在自己的另一台设备安装通用内容 | 经检查的标准构建包 |
| 在自己的设备之间迁移一场冒险 | 冒险管理导出的战役内容包 |
| 换机器继续同一场冒险 | 配套的战役进度包和玩家包，或整套私人备份 |
| 升级程序 | 关闭服务后替换主程序，保留同级模块与运行数据 |

不要用“压缩整个项目文件夹”代替迁移打包：那会带上不需要的私人资料、恢复备份以及开发历史。当前构建仅用于私人使用与技术验证；若将来改变为公开分享，需要重新检查分享边界。
